# src/generated -- member definitions and machine code

Generated by `tools/gen_bodies.py` and `tools/gen_code.py`. Do not edit by hand; regenerate with `./tools/pipeline.sh`.

## What is in here

`code/` holds the **machine code**: one transcription per recovered function VA, `ts::sub_XXXXXXXX(void)`, plus a registration unit so `ts_call()` reaches it. That is the faithful artifact and the one the gate checks.

The per-class `.cpp` files here hold **forwarders**: the out-of-line definitions the reconstructed headers require, each calling the canonical transcription of its VA. They are declaration-shaped, so they compile against the reconstructed tree; the code is not repeated in them.

6.94% of the recovered functions (3024 of 43564) are declared by the
reconstructed headers, so a forwarder exists for them. The other 40540 are
transcribed in `code/` regardless, but no reconstructed header declares
them -- see `code/` and `tools/gen_code.py`.

Every transcription is one machine instruction per generated line, with the
original instruction kept as a trailing comment, so a file can be read against
the recovered listing line for line.

This is not source-shaped decompilation. It is not claimed to be the shape the
original source had; it is claimed to be faithful to what the machine does.
